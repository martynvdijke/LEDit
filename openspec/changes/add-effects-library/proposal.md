## Why

LEDit already ships ambient animation — matrix rain (`render/matrixrain.go`), four screensaver variants (`render/screensaver/{starfield,dvd,matrix,plasma}.go`), and a metadata-driven audio visualizer (`render/visualizer/`, `datasource/audio.go`) — but each is a closed draw function with a fixed palette and no shared parameters: the visualizer hardcodes `#50fa7b` (`render/visualizer/visualizer.go:26`), matrix rain hardcodes its green palette (`render/matrixrain.go:14`), and every new animation means new Go code plus ad-hoc registration in two places (`handlers/sources.go:315`, `handlers/websocket.go:190-192,294`). Operators cannot retune speed/intensity/density, cannot color an animation from the active theme (`render/theme.go`, `openspec/specs/theme-designer`), and cannot reuse one animation across the feed, scenes, panels, overlays, and the screensaver slot. There is no effect picker, no parameter model, and no presets to store a tuned look. This change introduces a small procedural effects engine that generalizes the existing math behind one deterministic interface, so the library grows by parameter and registry entry instead of forking the render loop.

## What Changes

- **Effect registry and engine** in `render/effects/`: a common `Effect` interface evaluated per tick at the target resolution plus a named registry, with initial built-ins `plasma`, `fire`, `sparkle`, `scan`/`sweep`, `noise`, and `gradient` fields, and adapters that expose the existing screensaver/matrix-rain math through the engine. Every effect is parameterized by palette roles (theme colors), `speed`, `intensity`, `density`, `direction`, and `seed`, and output is deterministic given `(effect, params, seed, quantized time)`.
- **Theme integration**: effects consume the effective `render.Theme` (`render/theme.go`) resolved through the existing theme pipeline (`handlers/theme.go:46 ResolveTheme`, `themeOverrideFrom` at `handlers/theme.go:565`); the engine defines no literal brand colors. Existing `render/visualizer` and `render/matrixrain` stay byte-identical and may opt into the engine only when explicitly mapped to an effect.
- **Usable on every surface**: standalone selectable source (`effect:<preset>` in `buildSourceIndex`, `bindingOptions`, and the WebSocket source list, animated via the existing `datasource.Animator` path at `handlers/websocket.go:1497`), matrix cell / composition region / scene content (they already resolve through `sourceIndex`, e.g. `handlers/scenes.go:764`), screensaver/animated slot (opt-in), and background/overlay layers through the existing send-time seams (`render/overlay.go`, `render/composite.go`, `render/panel_canvas.go`).
- **Effect presets stored as artifacts**: a named `EffectPreset` entity (effect kind, validated parameters, optional built-in flag) persisted in Ent with admin CRUD, so a tuned effect is reusable across sources, scenes, overlays, and screensavers.
- **Admin authoring**: effect picker, parameter form (palette role preview, speed/intensity/density, direction, seed), and live preview through the existing `/admin/preview` family (`handlers/preview.go`, `AdminPreviewDatasource`) and the theme-editor preview pattern (`web/frontend/theme_editor.ts`).
- **Performance guardrails**: per-frame budgets benchmarked at 64×32, 128×64, and 256×128 (numbers documented in `design.md`), buffer reuse so a warm render loop allocates no per-frame scratch, and deterministic seeded golden-frame tests.
- **Constraints / non-goals**: no new required runtime dependency (stdlib `math`, `image`); existing screensaver, visualizer, and matrix-rain behavior is unchanged unless a source explicitly opts into the engine; the WebSocket frame protocol and the existing render loop are extended at existing seams, never forked.

## Capabilities

### New Capabilities
- `effects-library`: named procedural effect registry, parameter model (palette, speed, intensity, density, direction, seed), deterministic resolution-aware per-tick rendering, theme palette consumption, buffer reuse and documented performance budgets, and opt-in composition across the source, scene, panel/composite, background, and overlay seams.
- `effect-presets`: persisted named effect presets (effect kind + validated parameters), admin CRUD and picker, live preview through the existing preview endpoints, and assignment/resolution of presets to sources, scenes, overlays, and screensaver slots.

### Modified Capabilities
- None — the engine is additive. Existing `ambience-modes`, in-flight `screensaver-modes` / `audio-visualizer` / `overlay-layer`, and `theme-designer` requirements keep their current behavior; the opt-in adapters are specified as ADDED requirements inside `effects-library` instead of as deltas, mirroring how `add-fleet-ops` kept its interactions inside new capabilities.

## Impact

- **New code**: `render/effects/` (registry, parameter model, theme palette mapping, built-in effects, buffer-reusing renderer, unit + golden + benchmark tests), `datasource/effect.go` (`EffectDS` implementing `Datasource`, `ThemedRenderer`, and `Animator`), `ent/schema/effectpreset.go` (+ `go generate ./ent`), `handlers/effects.go` (preset CRUD, picker data, preview), `web/templates/admin/effects.html` / `effect_form.html`, `web/frontend/effect_editor.ts`.
- **Modified code**: `handlers/sources.go` (`buildSourceIndex`, `bindingOptions` add `effect:<preset>` entries), `handlers/websocket.go` (compose effect presets into the source list; reuse the animated re-render path; no frame-protocol change), `handlers/preview.go` (preset live preview), `render/overlay.go` (optional effect content for the strip, additive and default-off), `render/composite.go` / `render/panel_canvas.go` only where an opt-in composition helper is needed, and admin sidebar/nav registration.
- **API surface**: admin-only routes under `/admin/effects` (list/create/edit/delete) plus existing `/admin/preview` for live preview; no device-facing or WebSocket protocol changes; playlist and binding JSON gain `source_type:"effect"` / `source_id:<preset id>` items, which degrade through the existing dangling-source fallback when a preset is removed.
- **Dependencies**: none new — `image`, `image/color`, `image/png`, `math`, and the existing `math/rand` LCG patterns already used by `render/matrixrain.go` and `render/screensaver/matrix.go`.
- **Risk**: per-frame cost grows with pixel count (baseline: `DrawPlasma` at 64×64 is ~347 µs, ~85 ns/pixel on the benchmark host) and allocation churn would pressure the feed loop at ~15 fps; mitigated by buffer reuse, tick quantization, benchmark-enforced budgets, and keeping the effect pass a fraction of the existing per-frame PNG encode cost (measured: ~196 µs at 64×32, ~327 µs at 128×64, ~933 µs at 256×128). Legacy sources not opted in remain byte-identical, so the blast radius is limited to configured effects.
